# Lenz Project Notes

## Project Goal

This project studies candidate-selection for robust visual recognition under environment shifts.

There are two main parts:

1. `lens/`
   - Build candidate manifests over multiple sensor / parameter settings.
   - Use the visual backbone to score all candidates for a sample.
   - Select the best candidate with the Lens rule: pick the image with maximum softmax confidence.

2. `policy_network/static_pred/`
   - Train a policy network that only sees the baseline image.
   - Predict which candidate index / option should be chosen.
   - Feed the selected candidate back into the Lens visual classifier and evaluate final classification accuracy.

Current practical objective:
- Understand whether the policy network can select candidates that preserve or improve downstream accuracy.
- Compare three notions clearly:
  - teacher index imitation accuracy
  - final classification accuracy after policy selection
  - final classification accuracy after Lens confidence-based selection

Current backbone convention:
- Unless explicitly changed later, all current analysis and comparison should be treated as using `resnet50`.
- References to ViT / ViSIT in earlier discussion should not be treated as the active default setting for this project note.

- `data/ImageNet-ES-Diverse/policy_labels/policy_{train,val,test}_labels.json`: train / val / test splits for policy training.

- `policy_network/results/test_policy_selected_visit_acc.json`: downstream evaluation after feeding policy-selected candidates into the visual classifier.

Important code:
- `lens/generate_expert_label.py`: generates policy supervision labels from Lens selections.
- `lens/eval_lens.py`: evaluates Lens, random, and oracle-specific baselines.
- `lens/lens_core.py`: implements confidence-based candidate selection.
- `policy_network/static_pred/train_policy.py`: trains the policy network.
- `policy_network/static_pred/debug/eval_policy_selected_visit_acc.py`: compares policy-selected final accuracy against Lens-selected final accuracy.

## Current Understanding of the Pipeline

### Lens side
- For each sample there are multiple candidate images, each with an `option_id`.
- The classifier runs on all candidates.
- Lens selects the candidate with the largest max-softmax confidence.
- This selected candidate is stored as the expert target for policy training.
- In the current project notes, this classifier setup is treated as `resnet50`.

### Policy side
- Input: baseline image only, typically fixed `baseline_option_id = 13`.
- Output: a predicted candidate id / index.
- Supervision target: Lens-generated `best_option_id`.
- Evaluation can be done in two different ways:
  - index prediction accuracy: whether policy predicts the same candidate that Lens picked
  - final classification accuracy: whether the image chosen by policy leads to a correct class prediction

### Important terminology
- `option_id`: semantic candidate identity.
- `candidates` list position: where that candidate appears in the current sample's array.
- These are often numerically the same in the current manifests, but conceptually they are different and should not be conflated.

### 3. Clarified `option_id` vs list position
We explicitly checked the difference between:
- candidate semantic id: `option_id`
- candidate array position in `candidates`

Conclusion:
- the code should treat policy output as candidate identity and map it back to the actual position before indexing logits.
- even if current manifests often keep the same order, relying on equality between `option_id` and list position is fragile.

## New Progress Update

### 1. State augmentation was added to policy training
- `policy_network/static_pred/policy_dataset.py` was updated so training can sample a random candidate image from the same scene instead of always using the fixed baseline image.
- Current convention in training code:
  - train split: random candidate state augmentation
  - val/test split: fixed baseline image
- Reason:
  - increase effective input diversity for the same scene
  - reduce memorization of one fixed baseline appearance

### 2. Backbone freezing and partial unfreezing were implemented
- The policy model in `policy_network/static_pred/policy_model.py` is still based on `MobileNetV3-Small`.
- Several training regimes now exist:
  1. policy head only
  2. partial unfreeze for Stage 2
- Current Stage 2 setting:
  - lower backbone remains frozen
  - unfreeze `backbone[9:12]`
  - unfreeze `feature_proj`
  - keep `policy_head` trainable
- Current Stage 2 learning rates:
  - backbone tail + `feature_proj`: `5e-6`
  - `policy_head`: `1e-4`

### 3. Oracle GT labels were added
- A new script was created:
  - `policy_network/static_pred/generate_oracle_policy_labels.py`
- It generates a new label set in:
  - `data/ImageNet-ES-Diverse/oracle_policy_labels/`
- Oracle GT logic:
  - run all 27 candidates through the downstream `resnet50` classifier
  - if any candidate predicts the true class, select among correct candidates
  - if none are correct, select the candidate with minimum classification loss
- Existing Lens-based labels were not overwritten.

### 4. Soft-label training was added
- Oracle label generation now also stores `soft_target`.
- For samples with multiple correct candidates:
  - the soft target distributes probability mass over all correct `option_id`s
  - current default weighting mode is confidence-based among the correct candidates
- `policy_network/static_pred/train_policy.py` now supports:
  - `hard_ce`
  - `soft_kl`
  - `auto`
- `auto` chooses `soft_kl` when the dataset contains `soft_target`.

### 5. Resume training support was added
- `policy_network/static_pred/train_policy.py` now supports `--resume_checkpoint`.
- Current Stage 2 training resumes from:
  - `policy_network/results_oracle_policy/policy_net_freeze_soft.pth`
- Current `train_policy.sh` is configured as Stage 2 training:
  - Oracle labels
  - soft-label training
  - partial unfreeze
  - resume from the Stage 1 soft-label checkpoint

### 6. Debug / evaluation scripts were updated
- `policy_network/static_pred/debug/analyze_best_index_predictions.py`
  - fixed import path issue when running from `debug/`
- `policy_network/static_pred/debug/eval_oracle_upper_bound.py`
